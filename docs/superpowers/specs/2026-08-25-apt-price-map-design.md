# apt_price_map 설계안 — 서울시 아파트 실거래가 지도

- 작성일: 2026-08-25
- 상태: 승인됨 (브레인스토밍 단계 완료, 다음 단계: writing-plans)

## 목적

서울시 아파트(매매·전세·월세) 실거래가를 단지 단위로 집계해 지도에 표시하는
PWA. 기존 지도 앱 시리즈(museum_map, library_map, hospital_map 등)와 동일한
구조로 만들어 daitmap 포트폴리오에 합류시킨다.

## 범위

- 지역: 서울특별시 전체 (25개 자치구)
- 기간: **2025년 ~ 2026년 거래만** (그 이전 데이터는 가져오지 않는다)
- 물건: **아파트만** (연립다세대·단독다가구·오피스텔 등은 제외)
- 거래 유형: 매매 + 전세 + 월세 모두

## 데이터 출처

서울 열린데이터광장(data.seoul.go.kr) OpenAPI, 두 개의 독립 데이터셋:

| 데이터셋 | 용도 |
|---|---|
| `OA-21275` 서울시 부동산 실거래가 정보 | 매매 |
| `OA-21276` 서울시 부동산 전월세가 정보 | 전세·월세 |

두 데이터셋 모두 좌표(위도/경도)를 포함하지 않는다 — 지오코딩 필요.
인증키는 서울 열린데이터광장에서 신규 발급해 `.env`의 `SEOUL_OPENDATA_KEY`로
관리한다 (다른 지도 프로젝트의 `KAKAO_REST_KEY`와 같은 패턴).

### 아파트 필터링 함정

두 데이터셋 모두 아파트 외 물건종류(연립다세대, 단독/다가구, 오피스텔 등)가
섞여 있다. **단지명에 "아파트"가 들어가는지로 판단하지 않는다** — 오탐이
생긴다(예: 아파트가 아닌데 이름에 들어가는 경우, 반대로 아파트인데 이름에
없는 경우). 실제 API 응답을 받아본 뒤 물건종류를 나타내는 정확한 필드명과
값을 확인해 필터링 조건을 구현 단계에서 확정한다. 이 확인 자체를 구현 계획의
첫 작업으로 둔다.

## 데이터 파이프라인 (`tools/`)

1. **`fetch_sale.py`** — `OA-21275` 호출, 2025~2026년만, 원자료를 로컬(중간
   산출물)에 저장
2. **`fetch_rent.py`** — `OA-21276` 호출, 동일 기간
3. 위 아파트 필터링을 두 스크립트 모두에 적용
4. **`geocode.py`** — 두 원자료에서 단지명+지번주소 조합을 유니크하게 뽑아
   카카오 로컬 API로 좌표 조회. 캐시 파일(`tools/geocode_cache.json`)에
   저장해 재실행 시 중복 호출을 피한다.
5. **`build_data.py`** — 단지(자치구·법정동·단지명·주소) 단위로 집계해
   `assets/js/data.js` 생성:
   - 매매: 평균 평당가, 최근 거래가, 거래 건수, 최근 거래일
   - 전세: 평균 보증금, 평당 보증금, 거래 건수, 최근 거래일
   - 월세: 평균 보증금+월세, 거래 건수, 최근 거래일

## 지도 UI

- 마커는 단지 단위. 클릭 시 팝업에 해당 단지의 최근 거래 내역 목록(층·면적·
  가격·날짜)을 보여준다.
- 상단에 **매매 / 전세 / 월세 토글**. 모드를 바꾸면 같은 지도에 해당 거래
  유형만 다시 그린다 — 매매가(원)와 보증금(원)은 단위가 달라 하나의 색상
  척도를 공유할 수 없기 때문에 모드별로 분리한다.
- 마커 색상은 평당가(또는 평당 보증금) 구간별 색상 척도로 표시한다.
- 서울 아파트 단지 수(약 4천~5천 단지 추정)를 고려해, shelter_map /
  medicine_map이 공유하는 `render.js`의 줌 레벨별 집계 패턴(시도→시군구→개별
  마커)을 서울 전용으로 변형해(구→동→개별 마커) 재사용한다.
- 이모지 금지, 아이콘은 인라인 SVG(`class="ico"`, `viewBox="0 0 24 24"`) —
  기존 지도 프로젝트 규칙 그대로 따른다.
- 독도는 기존 `markDokdo()` 로직을 그대로 넣는다. 서울 전역이 보이는 초기
  화면에서는 독도가 화면 밖이라 보이지 않는데, 이는 의도된 것으로 두고
  사용자가 지도를 축소하면 보이도록 한다.
- `assets/js/geo.js`("내 주변") 공유 파일 연동은 이번 범위에 넣지 않는다
  (선택 사항, 나중에 필요하면 추가).

## 에러·엣지 케이스

- **API 페이지네이션**: 서울 열린데이터광장 OpenAPI는 요청당 최대 건수 제한이
  있을 가능성이 높다 — 실제 한도는 구현 단계에서 첫 호출로 확인한다.
- **주소 중복/단지명 표기 흔들림**: 같은 단지가 시점마다 다른 표기로 들어올
  수 있어, 집계 키를 단지명 문자열만이 아니라 지번주소까지 포함해 잡는다.
- **지오코딩 실패**: 카카오 API가 좌표를 못 찾는 주소는 별도로 로그를 남기고
  집계에서 제외하거나 수동 보정 목록에 올린다 (medicine_map의 EPSG 관련
  사례처럼 함정이 있을 수 있음 — 실제 데이터로 검증 필요).
- **거래 0건 단지**: 특정 모드(예: 월세)에서 거래가 없는 단지는 해당 모드에서
  마커를 그리지 않는다.

## 테스트/검증

- 각 `tools/*.py` 스크립트는 실행 후 산출물 건수·샘플을 콘솔에 출력해 사람이
  눈으로 확인할 수 있게 한다 (다른 지도 프로젝트의 관례).
- `build_data.py` 산출물에서 서울 25개 자치구가 모두 등장하는지, 매매/전세/
  월세 각 모드에서 마커 수가 0이 아닌지 확인한다.
- 브라우저에서 정적 서버로 열어 세 모드 토글, 줌 레벨별 집계 단계 전환,
  단지 클릭 팝업을 직접 확인한다.
